# Epic 3 Context: 성과 배수 스코어링 엔진 (Scoring)

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

각 영상이 "채널 평소 대비 몇 배" 성과인지 규모 편향 없이 판정하는, 이 제품의 핵심 방법론을 세운다. Epic 2가 축적한 일별 스냅샷을 읽어 채널·유형별 기준선(중앙값) → 성과 배수 → 플루크 방어 → 에버그린 후보 → 구독자 밴드/정렬키를 배치가 계산해 DB 컬럼·테이블에 물질화한다. 아직 화면은 없고, 값이 DB에 존재하는 것으로 에픽이 완성된다(Epic 6이 이 값을 읽어 렌더). 이 스코어링 스테이지들은 `DailyCollectionJob` 체인의 스냅샷 저장 뒤에 순서대로 append되어, 이후 Epic 4·5 스테이지가 이어 붙는다.

## Stories

- Story 3.1: 채널·유형별 기준선(중앙값) 계산 + 신뢰도 하한 플래그
- Story 3.2: 성과 배수 계산 + 플루크 방어(조회수 하한·극단배수) + 성과/모멘텀 축 분리
- Story 3.3: 구독자 밴드 4티어 티어링 + 결정적 기본 정렬키
- Story 3.4: 에버그린 후보 판정(대리지표, 1일차 동작) + 체인 append

## Requirements & Constraints

- 성과 배수 = 영상 현재 누적 `view_count` ÷ 같은 채널·같은 `video_type` 최근 N개 공개 영상 `view_count`의 **중앙값**. 평균 아님, age-matched 아님(소급 불가라 MVP는 누적 사용, 편향은 명시)(FR-5).
- 신뢰도·플루크 방어(FR-6) — 유형별 최근 공개 영상 10개 미만이면 `low_confidence` 플래그, 조회수 하한 미만 영상은 배수 순위에서 기본 제외, 성과 배수 25배 초과는 "검증 요망" 플래그.
- 성과 배수(성과)와 VPD(모멘텀)는 별도 축으로 유지하며 하나의 종합 점수로 합산하는 코드 경로가 없어야 한다(FR-7). VPD 값 계산은 이 에픽 범위 밖(축 분리 원칙만).
- 구독자 밴드 4티어(<1만/1만~10만/10만~50만/50만+)를 계산한다. 밴드는 필터·그룹핑 축이지 배수의 분모가 아니다(FR-10 계산 부분, 표시·평면 토글은 Epic 6).
- 에버그린 후보는 나이(경과일 ≥ 기준일) AND 성과 배수(≥ 임계) 두 조건 동시 충족 시에만 "후보"로 라벨링한다. 배수>1을 후보 기준으로 쓰지 않고, "에버그린"으로 단정하지 않는다. 스냅샷 없이 현재 조회수·업로드일·기준선만으로 계산해 1일차부터 동작한다(FR-13).
- 검증 승격(FR-14)의 값은 이 에픽에서 계산하지 않는다 — `VideoDailyStat` 스키마가 미래 소재지로 자리만 유지한다(MVP Out of Scope).
- 검증 픽스처는 자사 실측 조회수 200~4,100 범위를 쓴다. 중앙값 계산·유형 미공유·nil 제외·조회수 하한 상대식·극단배수 상한을 테스트로 고정한다.

## Technical Decisions

- **스코어링 단일 소재지 (AD-2)** — 기준선·성과 배수·플루크 방어·정규화는 오직 `app/services/scoring/*`에서 계산한다. 뷰·잡·모델에 공식을 복제하지 않는다. 지표 정의(중앙값 기준선·누적 조회수 분자·축 분리)를 코드에 못박는다. 서비스는 `Scoring::CalculateBaseline` 같은 동사형 클래스.
- **배치 물질화, 요청 경로는 읽기만 (AD-3)** — 기준선·성과 배수·밴드·에버그린 후보 플래그는 배치가 DB 컬럼/테이블에 써두고, 웹 요청 경로는 재계산하지 않는다(중앙값 재계산 금지, P95 2초).
- **튜닝값은 `config/scoring.yml`에서만 (AD-4)** — 기준선 N·조회수 하한(고정값·k)·극단배수 임계(25x)·에버그린 나이/배수 임계·`is_short` duration 임계·구독자 규모 임계를 코드 상수로 하드코딩 금지. 값은 본개발 실측이고 구조·자리만 고정. 픽스처도 이 파일 경로로 읽어 하드코딩 회귀를 테스트가 잡게 한다.
- **쇼츠/롱폼 완전 분리 (AD-8)** — 기준선·필터·표시에서 쇼츠와 롱폼의 중앙값을 절대 공유하지 않는다(channel-analysis 실측 — 쇼츠 중앙값이 롱폼의 약 2.7배). `is_short`는 Epic 2의 `Youtube::ClassifyShort`가 최초 저장 시 판정한 캐시값을 읽기만 한다(이 에픽은 재판정하지 않음).
- **nil 방어 (AD-9)** — 회원 전용(`view_count` nil) 영상은 기준선 표본·성과 비교에서 제외하되 파이프라인을 중단하지 않는다.
- **정직성 플래그 물질화 (AD-16)** — `low_confidence`(저신뢰), 25x 초과 "검증 요망", "에버그린 후보"는 스코어링이 계산해 DB에 심어두고, Epic 6이 위젯을 숨기지 않고 자리를 유지하며 렌더한다. 조회수 하한 미만 영상은 순위에서 빠지되 값은 유지한다.
- **데이터 모델 (물질화 대상)** — `Baseline(channel, video_type, median, sample_size, low_confidence)`. 성과 배수·밴드·에버그린 후보 플래그는 `Video`(또는 파생 컬럼)에 물질화. AR 모델은 단수 PascalCase, YouTube 식별자는 `youtube_*_id`.

## UX & Interaction Patterns

- **기본 정렬키는 성과 배수 내림차순** (AD-15) — 이 에픽이 정렬키를 산출한다. raw 조회수 기본 정렬 금지. 기본 레이아웃은 구독자 밴드 그룹핑 + 밴드 내 배수 정렬(표시는 Epic 6).
- **시점 편향 두 기전 (FR-24)** — 성과 배수의 편향을 두 가지로 명명한다 — (1) 현재 누적 조회수 사용, (2) 기준선이 최근 N개(젊고 저조회) 영상이라 오래된 영상 배수를 추가로 부풀림. 에버그린 후보 판정이 이 편향을 상속한다(코드 주석으로 명시). 실제 문구·툴팁 렌더는 Epic 6.

## Cross-Story Dependencies

- 스토리 순서는 계산 의존을 그대로 따른다 — 3.1 기준선(중앙값·신뢰도) → 3.2 성과 배수·플루크 방어 → 3.3 밴드·정렬키 / 3.4 에버그린 후보(둘 다 3.2에 의존). Epic 2의 Story 2.4(일별 스냅샷)가 전제다.
- **체인 append (AD-11)** — Epic 3의 스테이지(기준선 → 성과 배수 → 에버그린 후보)는 `DailyCollectionJob` 체인의 스냅샷 저장 뒤에 순서대로 붙는다. 각 스테이지는 이전 산출을 DB에서 읽어 다음을 쓴다(한 파생값의 writer는 한 스테이지뿐). 이후 Epic 4(임베딩·OwnVideoMatch·갭·클러스터), Epic 5(기회 점수·추천)가 체인 뒤에 이어진다.
- **하류 소비자** — 성과 배수·밴드·에버그린 후보 플래그는 Epic 6(대시보드·급상승·에버그린 탭)이 표시하고, 성과 배수·최신성 신호는 Epic 5의 기회 점수 4입력 중 일부로 소비된다. Epic 4(임베딩)는 조회수와 무관해 이 에픽과 병렬 진행 가능하다.
