# Epic 6 Context: 대시보드 & 6화면 (Presentation)

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

MVP의 표현 계층을 완성한다. 앞선 에픽(2~5)이 배치로 DB에 물질화해둔 값(성과 배수·기회 점수·추천 3개·콘텐츠 갭 버킷·자사 유사영상·에버그린 후보·일별 스냅샷)을 읽어, 좌측 내비 6화면(대시보드 홈 / 인기 콘텐츠 / 경쟁 채널 / 콘텐츠 갭 / 저장한 영상 / 설정) 위에 얹는다. 웹 요청 경로는 계산하지 않고 물질화된 컬럼을 읽기만 한다(AD-3, P95 2초). 목표는 운영자가 한 화면에서 추천·급상승·경쟁·갭·에버그린을 훑고 10분 안에 다음 주 주제 3개를 결정하는 것(SM-1)이다. 모든 화면 스토리는 empty/loading/error·콜드스타트·정직성·다국어·반응형 AC를 공통으로 포함하며, 6.1이 공유 표시 컴포넌트를 먼저 못박고 나머지 화면이 그 위에 얹힌다.

## Stories

- Story 6.1: 공유 표시 컴포넌트 (배수 셀 · 정직성 상태 · 테이블 행 · 헬퍼)
- Story 6.2: 대시보드 홈 — 추천 3개 + 기간 탭 + 필터 바
- Story 6.3: 인기 콘텐츠 — 급상승 영상 테이블 + 스파크라인
- Story 6.4: 경쟁 채널 화면 — 동향 + 수동 등록/제외 + 구독자 증감
- Story 6.5: 콘텐츠 갭 화면 — 도넛 분포
- Story 6.6: 에버그린 탭 — 후보 표시 + 검증 "수집 중"
- Story 6.7: 설정 화면 — 수집 상태 + 계정

## Requirements & Constraints

- **6화면 + 에버그린 탭** — 좌측 내비는 대시보드 홈/인기 콘텐츠/경쟁 채널/콘텐츠 갭/저장한 영상/설정의 6개다. "에버그린"은 별도 7번째 내비가 아니라 FR-9의 **에버그린 기간 탭** 콘텐츠로 대시보드·인기 콘텐츠 안에서 렌더된다(6.6). 앱 셸(헤더·사이드바·6라우트)은 Story 1.4에서 이미 존재하며, 이 에픽은 각 라우트에 얇은 읽기 전용 컨트롤러와 뷰를 채운다.
- **웹 경로는 읽기 전용(AD-3)** — 성과 배수·기회 점수·콘텐츠 갭 버킷·자사 유사영상·에버그린 후보는 배치가 이미 DB에 써뒀다. 요청 경로에서 임베딩·유사도·중앙값·정규화를 재계산하지 않는다. 컨트롤러는 물질화된 값을 조회·정렬해 뷰에 넘길 뿐이다. 이 에픽은 UI 드리프트 위험이 가장 큰 지점이므로 계산 유입을 특히 경계한다.
- **성과 배수 색 밴드(FR-8, 전 화면 동일)** — 순차 그린 램프뿐이다. `<2배` 중립(muted) / `2~5배` / `5~10배` / `>10배` solid. amber·red는 성과 배수에 절대 쓰지 않는다. 매핑은 `performance_band_class` 헬퍼 한 곳에서만 나오고 6화면이 이를 공유한다(DESIGN.md §1.5·§10).
- **정직성 5상태는 숨기지 않고 자리 유지(AD-16)** — 데이터 수집 중 / 측정한계 / 에버그린 후보 vs 검증 / 검증 요망 / 저신뢰. 값이 없어도 위젯을 감추지 않고 목업 자리를 유지한다. 콜드스타트는 전역 배너 하나로 뭉개지 말고 **위젯별 준비도**로 "D+n 데이터 수집 중"을 개별 판정한다(AD-7). 시점 편향 안내(FR-24)는 성과 배수 옆/툴팁에 두 기전을 모두 명명한다 — (1) 누적 조회수 사용, (2) 기준선이 최근 N개 젊은 영상.
- **라벨 통일(강제)** — "구독자 대비 조회수" 표현이 코드·뷰 어디에도 없어야 하고 전부 "성과 배수(채널 평소 대비)"로 통일한다(PRD §11, DESIGN.md §9).
- **기본 표시 규약** — 기본 정렬키는 성과 배수 내림차순이고, 기본 레이아웃은 구독자 밴드 그룹핑 + 밴드 내 배수 정렬(평면 토글 가능)이다. 성과 배수는 히어로 셀, raw 조회수는 2차 뮤트 컬럼이다. raw 조회수 기본 정렬은 금지다.
- **다국어(한·일 혼재 제목) 오버플로 방어(§7)** — 제목·채널명 셀에 폰트 폴백(Pretendard/Noto Sans KR/JP)·`word-break:keep-all`·line-clamp/truncate + `title` 툴팁·`min-w-0`·`lang` 힌트를 적용한다. 실데이터에서 반드시 터지는 지점이다.
- **반응형(§5)** — 좌측 내비는 모바일에서 축소(햄버거 드로어/아이콘 레일), 테이블은 좁은 화면에서 `overflow-x-auto` 가로 스크롤(셀에 `min-width`)로 처리한다. 본문 자체가 가로로 깨지는 것은 금지다.

## Technical Decisions

- **프론트 스택은 Rails 뷰 + Tailwind v3** — `tailwindcss-rails`(v3 핀 필수, 기본이 4.x라 설치 시 v3로 고정), Hotwire(Turbo/Stimulus), propshaft, importmap. **ViewComponent gem은 쓰지 않는다.** 공유 컴포넌트는 `app/views/shared/_*.html.erb` partial + `app/helpers`로 캡슐화한다(AD-15).
- **DESIGN.md가 토큰 단일 원천(AD-15)** — 색·간격·radius·타입 스케일·성과 밴드·정직성 스타일의 권위는 DESIGN.md 전문에 있다. §10 토큰은 이미 `config/tailwind.config.js`의 `theme.extend`(primary/success/warning/mult/badge/text/border)로 이관돼 있다. 원시 Tailwind 색(`blue-600` 등) 직접 사용은 금지다 — 6화면이 서로 다른 세션에서 만들어지므로 토큰을 세션마다 추정하면 화면이 어긋난다.
- **얇은 읽기 전용 컨트롤러** — Model·View·Helper는 Service를 부르지 않는다(의존 방향). 컨트롤러는 물질화된 AR 값을 조회·정렬만 하고, 표시 로직(밴드 클래스·정직성 상태·다국어 방어)은 헬퍼·partial에 캡슐화한다.
- **공유 위젯 목록(6.1)** — `shared/_performance_cell`(배수 히어로 셀 + raw 조회수 뮤트), `performance_band_class` 헬퍼(§1.5 램프 매핑), `shared/_video_row`(썸네일·제목·채널·업로드일·조회수·배수·자사 유사영상·유형 배지·구독자 밴드), `shared/_honesty_status`(5상태 §4.7 스타일). 나머지 5화면이 이 위젯을 재사용한다.
- **편향 기전 명명 위치** — 성과 배수 근처(옆/툴팁)에 누적 조회수·젊은 N개 기준선 두 편향을 모두 명명한다. 이 문구도 공유 위젯에 넣어 6화면이 일관되게 표시하게 한다.

## UX & Interaction Patterns

- **대시보드 홈(6.2)** — 상단 "이번 주 추천 콘텐츠 3개" 카드(번호 뱃지 1·2·3, 기회 점수 큰 숫자, "근거 보기" 펼침). 기간 탭(최근 1주/1개월/3개월 + 에버그린)이 업로드 기간 필터로 동작(콜드스타트에서도). 카테고리·유형 드롭다운(한국어 교육/영어 교육/일반 + Shorts). 시계열 위젯(VPD 급상승·트렌드 스파크라인·검증 에버그린·구독자 증감)은 위젯별 "D+n 수집 중"으로 자리 유지. empty(추천 0 → "N개 확보")·loading(스켈레톤)·error 각각 표시.
- **인기 콘텐츠(6.3)** — 급상승 테이블. 컬럼: 순번/영상(썸네일+제목)/채널/업로드일/조회수/성과 배수/트렌드(7일 스파크라인)/자사 유사영상. 배수는 색 밴드, raw 조회수는 뮤트 컬럼, 유형 배지·구독자 밴드·주제 힌트 표시. 행 클릭 시 유튜브 URL 이동. 스파크라인은 시계열 의존이라 콜드스타트에 "데이터 수집 중" 플레이스홀더로 자리 유지.
- **경쟁 채널(6.4)** — 채널명·구독자·(조건부)구독자 증감 리스트. URL 입력 시 `Channel(source: manual)` 추가(다음 수집 주기 반영), 제외 채널은 대시보드·채점에서 빠짐. 구독자 증감은 7일 스냅샷 후 규모 임계(`scoring.yml`) 이상만 표시, 미만은 "측정한계" 라벨.
- **콘텐츠 갭(6.5)** — 콘텐츠 기회 도넛(4구간 비율·건수) + 범례. 각 행의 자사 유사영상 컬럼과 도넛 분류가 일치. 임베딩 미완 시 "준비 중"으로 자리 유지. 도넛은 `primary` 톤 램프 + neutral 1개, 중앙 `text-score`(§4.6).
- **에버그린 탭(6.6)** — FR-9 에버그린 기간 탭 안에서 렌더. 후보는 "에버그린 후보" 라벨로 1일차부터 표시, 검증 에버그린은 "데이터 수집 중"으로 자리 유지(스냅샷 축적 후, MVP Out of Scope). 후보와 검증을 시각적으로 구분.
- **설정(6.7)** — 최근 수집 이력(성공/실패/재시도/쿼터 사용량, `job_runs` 기반), 데이터 범위·백업 상태 안내, 계정(로그아웃).
- 렌더 상세는 스토리별로 확정하되, 위 요소는 PRD·DESIGN.md에서 이미 고정된 데이터·컴포넌트 요건이다.

## Cross-Story Dependencies

- **에픽 내부** — 6.1(공유 표시 컴포넌트)이 먼저다. 6.2~6.7은 배수 셀·정직성 상태·비디오 행·헬퍼를 6.1에서 재사용하므로 6.1이 완성돼야 나머지 화면이 일관되게 렌더된다.
- **6.1의 상류 전제** — 6.1은 Story 3.2(성과 배수)·5.2(추천 3개)·1.3(디자인 토큰/tailwind config)에 의존한다. 밴드 매핑·추천 카드 요건·토큰이 모두 앞서 존재해야 한다.
- **화면별 상류 전제** — 6.2는 5.2(추천)·Epic 3(배수), 6.3은 3.2(배수)·4.2(자사 유사영상)·2.4(스냅샷/스파크라인), 6.4는 2.6(주간 발굴/수동 채널)·2.4(구독자 증감), 6.5는 4.3(콘텐츠 갭 버킷), 6.6은 3.4(에버그린 후보), 6.7은 2.5(수집 잡/`job_runs`)가 물질화한 값을 읽는다.
- **하류** — Epic 7(검색·필터·정렬·저장)이 이 화면들 위에 탐색·저장 기능을 얹는다. 6화면의 공유 컴포넌트와 필터 바가 Epic 7의 기반이 된다.
