# Epic 4 Context: 임베딩 · 자사 유사영상 · 콘텐츠 갭 (Similarity)

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

후보 주제를 자사가 이미 다뤘는지, 경쟁 대비 자사 커버리지 공백이 어디인지 판정하는 유사도 인프라를 세운다. 영상 제목 임베딩을 만들어 BLOB로 저장하고, Ruby 코사인으로 경쟁 영상마다 자사 유사영상을 매칭하며, 그 결과를 콘텐츠 갭 4구간으로 분류하고, 같은 임베딩을 재사용해 영상을 주제 단위로 자동 묶는다. 임베딩은 조회수와 무관하므로 성과 배수를 다루는 Epic 3과 병렬 진행 가능하다. 아직 화면은 없고, 배치가 계산해 물질화한 값이 DB에 존재하는 것으로 에픽이 완성된다(Epic 6이 콘텐츠 갭 화면·급상승 행의 자사 유사영상 컬럼으로 렌더, Epic 5가 주제 클러스터를 추천 단위로 소비). 이 스테이지들은 `DailyCollectionJob` 체인의 에버그린 후보 뒤에 순서대로 append된다.

## Stories

- Story 4.1: 임베딩 생성·저장 (제목 변경 시만 재생성)
- Story 4.2: 자사 유사영상 판정 (OwnVideoMatch)
- Story 4.3: 콘텐츠 갭 4구간 버킷
- Story 4.4: 임베딩 기반 주제 자동 묶기 (연결요소)

## Requirements & Constraints

- 자사 유사영상 판정(FR-17) — 경쟁 영상마다 주제가 가까운 자사 영상이 있는지 임베딩 유사도로 판정한다. 임베딩은 영상당 1회 생성하되 저장된 제목이 바뀐 행은 재생성한다(크리에이터가 제목을 A/B로 자주 바꾸므로). 과금은 신규 영상 + 제목 변경분에만 발생한다.
- 콘텐츠 갭 분포(FR-18) — 경쟁 영상 주제 대비 자사 커버리지를 미제작 / 유사영상 1개 / 유사영상 2개+ / 포화의 4구간으로 분류·물질화한다. 이 분류는 급상승 영상 행의 자사 유사영상 컬럼 표시와 반드시 일치한다.
- 주제 자동 묶기(FR-20) — §4.7과 같은 임베딩을 재사용해 코사인 유사도 ≥ τ인 영상 쌍을 간선으로 잇고 연결 요소(connected components)를 하나의 주제 클러스터로 본다. 일·한 교차 묶기이며 추가 임베딩 비용이 없다. 스냅샷이 아니라 임베딩에 의존해 1일차부터 동작한다.
- τ는 알려진 중복/비중복 제목 쌍으로 본개발에서 실측 튜닝하는 값이고, 묶기 간선 τ는 FR-17 판정 τ를 재사용한다(고정 0.8 맹신 금지).
- 코스(회원 전용) 자사 영상은 제목·주제 매칭까지만 되고 성과 수치는 표시하지 않는다 — API가 회원 영상 통계를 주지 않아 강제되는 명시적 한계다(AD-9).
- 유사도·묶기는 배치에서만 계산해 물질화하고 웹 요청 경로는 읽기만 한다(임베딩·코사인 재계산 금지).
- 하류 검증 매핑 — SM-6(자사 중복 확인)이 FR-17·FR-18을, SM-2(근거 있는 주제 3개)가 FR-19·FR-21을 검증한다.

## Technical Decisions

- **임베딩은 BLOB + Ruby 코사인 (AD-10)** — `gemini-embedding-001`(유료 결제, credentials/ENV 키, YouTube와 같은 Google 계정·다른 키)로 제목 임베딩을 만들어 `videos`의 packed-float BLOB 컬럼에 저장하고, `embedding_source_hash`(제목 기준)를 함께 저장한다. 배치가 BLOB를 메모리로 올려 Ruby 코사인으로 유사도를 계산한다. **sqlite-vec 미채택**(벡터 5만 초과 시 드롭인 전환, N≈500 규모엔 Ruby 코사인으로 충분). 무료 티어에 의존하지 않는다.
- **재생성은 변경분만** — 신규 영상 + `embedding_source_hash`가 바뀐 행만 재임베딩한다. 매 배치 전량 재임베딩 금지(과금 방어). 최초 백필(자사 500 + 경쟁 과거분 ~1.5만)은 정상 일일 체인과 분리된 1회성 `BackfillJob` seam으로 두고, 월 운영비는 신규 영상 과금만이라 $1 미만이다.
- **외부 호출은 서비스 경계에서만 (AD-1)** — Gemini 호출은 오직 `app/services/embedding/*`를 통과한다. 컨트롤러·모델·뷰·잡에서 SDK 직접 호출 금지. 임베딩 생성·코사인·클러스터가 이 도메인에 모인다. 서비스는 동사형 클래스(`Embedding::UpsertVectors`).
- **배치 물질화, 요청 경로는 읽기만 (AD-3)** — `OwnVideoMatch`·콘텐츠 갭 버킷·주제 클러스터는 배치가 DB에 써두고 웹 요청 경로는 재계산하지 않는다(P95 2초).
- **튜닝값은 `config/scoring.yml`에서만 (AD-4)** — 유사도 임계 τ를 코드 상수로 하드코딩 금지. 값은 본개발 실측이고 스파인은 자리만 고정한다.
- **주제 클러스터는 휘발성 (AD-10)** — `TopicCluster`(연결요소)는 배치마다 재계산되는 휘발성이다(`relatedToVideoId`/관련영상 API 미사용). 따라서 `Recommendation`은 휘발 클러스터에 FK하지 않고 생성 시점의 `reference_video_ids` + `topic_label`을 스냅샷으로 저장한다(재라벨링돼도 추천이 댕글링되지 않음) — 이 소비는 Epic 5.
- **데이터 모델 (물질화 대상)** — `OwnVideoMatch(competitor_video_id, own_video_id, similarity)`가 유사영상 판정과 콘텐츠 갭 버킷의 근거다. `TopicCluster`는 배치 재계산 대상. AR 모델은 단수 PascalCase, YouTube 식별자는 `youtube_*_id`. 임베딩 BLOB·`embedding_source_hash`는 `videos`에 상주한다.
- **nil 방어 (AD-9)** — 코스(회원 전용, `view_count` nil) 자사 영상은 임베딩·유사 매칭에는 참여하되 성과 수치는 결과에 싣지 않는다.

## UX & Interaction Patterns

- **콘텐츠 갭 4구간 표시** — 미제작 / 유사영상 1개 / 유사영상 2개+ / 포화의 4구간 분류가 콘텐츠 갭 화면의 분포와 급상승 영상 테이블 행의 "자사 유사영상"(없음 / N개) 컬럼에 동일 값으로 나타나야 한다(두 표시가 어긋나면 안 된다). 실제 렌더는 Epic 6.

## Cross-Story Dependencies

- 스토리 순서는 계산 의존을 따른다 — 4.1 임베딩 생성·저장 → 4.2 OwnVideoMatch → 4.3 콘텐츠 갭 버킷의 선형 사슬이고, 4.4 주제 묶기는 4.1(임베딩)에만 의존해 4.2·4.3과 병렬 가능하다. 콘텐츠 갭은 OwnVideoMatch 없이, OwnVideoMatch는 임베딩 없이 계산할 수 없다.
- **Epic 상류 전제** — Epic 2의 Story 2.3(영상 열거·저장)과 Epic 1의 Story 1.5(scoring 설정·credentials seam)가 전제다. 임베딩은 조회수와 무관해 성과 배수 Epic 3과 병렬 진행 가능하다.
- **체인 append (AD-11)** — Epic 4의 스테이지(임베딩(신규/제목변경만) → OwnVideoMatch → 콘텐츠 갭 버킷 → 주제 클러스터(휘발))는 `DailyCollectionJob` 체인에서 Epic 3의 에버그린 후보 뒤에 순서대로 붙는다. 각 스테이지는 이전 산출을 DB에서 읽어 다음을 쓴다(한 파생값의 writer는 한 스테이지뿐).
- **하류 소비자** — 콘텐츠 갭 버킷·자사 유사영상은 Epic 6(콘텐츠 갭 화면·급상승 행)이 표시하고, 콘텐츠 갭은 Epic 5 기회 점수의 4입력 중 하나로, 주제 클러스터는 Epic 5 추천의 묶기 단위로 소비된다(체인 마지막에 기회 점수·추천 3개가 이어 붙음).
