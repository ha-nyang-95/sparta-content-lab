## 1. PRD 대조

### 착지 확인된 것 (양호)

- FR-23 콜드스타트 위젯별 준비도(전역 배너 금지) → AD-7이 정확히 포착(원문 "전역 배너 하나로 뭉개지 않는다"까지 반영).
- FR-17/20 임베딩 재사용·제목변경 시만 재생성·연결요소 클러스터 → AD-10에 충실.
- FR-22 조건부 구독자 증감(규모 임계·측정한계·channels.list 동승 0비용) → AD-5 + FR-22 바인딩 + AD-16.

### 갭 상세

**G2 — FR-19 "3개 억지 금지" 정직성 규칙 + 결정적 동점처리 (Medium).**
FR-19 consequence 두 줄이 스파인에서 사라졌다.
- *"자격 주제가 3개 미만인 주간에는 … 'N개 확보'로 정직하게 표시한다(3개를 억지로 만들지 않는다). 이는 SM-2를 조건부로 완화한다."* — 이건 **정직성 규칙**인데 AD-16(정직성 상태: 콜드스타트·측정한계·후보vs검증·저신뢰·시점편향)의 열거에 "추천 N개 확보" 상태가 없다. 대시보드 최종 산출물(추천 3개 카드)의 정직성 표면이 통째로 누락됐다.
- *"동점 처리는 결정적이다 — 기회 점수 → 성과 배수 → 최신성"* — **결정성(determinism) 불변식**인데 어떤 AD에도 없다. 랭킹 재현성을 좌우하므로 `services/scoring`의 불변식으로 고정돼야 한다.

**G3 — raw 조회수 강등 / 성과배수 히어로 / 기본 정렬 불변식 (Medium).**
FR-8·제약9의 핵심 3개 거동이 불변식으로 미명시.
- *"기본 정렬 키 = 성과 배수 내림차순(raw 조회수 기본 정렬 금지)"* — 이 프로젝트의 "공정 비교" 논지 전체를 떠받치는 거동. AD-15는 "성과배수 셀·뱃지" 파셜 캡슐화만 말하고, **정렬키·강등은 언급하지 않는다.** 이건 DESIGN 토큰이 아니라 컨트롤러/쿼리 거동이라 "DESIGN.md 참조"로 전이 커버되지 않는다(G3의 핵심).
- raw 조회수 2차 뮤트 컬럼 강등 — DESIGN §4.3에는 있으나 스파인 불변식 없음.
- 성과배수 4구간 색밴드는 AD-15 → `performance_band_class` 참조로 착지 ✓.

**G5 — FR-24 두 번째 기전 (Low-Medium).**
AD-16은 *"성과 배수 옆에 … 편향 안내를 둔다(FR-24, 두 기전 모두 명시)"* 로 "두 기전"을 인지는 한다. 그러나 FR-24/FR-5가 요구하는 **기전 (2)를 명명하지 않는다** — "기준선을 최근 N개(젊고 저조회) 영상으로 잡아 오래된 영상 배수를 추가로 부풀림". 또 FR-13 consequence *"FR-5의 기준선 증폭 편향을 상속하므로 승격 전에는 후보로만"* 의 **상속 논거**가 스파인에 없다. AD-2(기준선 계산)도 이 증폭 방향성을 언급하지 않는다. 안내 문구가 "누적 조회수만 탓하지 않게" 하는 게 FR-24의 명시 요구인데, 스파인 텍스트만 보고 구현하면 (1)만 안내할 위험이 남는다.

**G6 — FR-21 정규화 구조 (Low-Medium).**
AD-4가 "기회 점수 가중치와 정규화 매핑"을 통째로 config로 위임했다. 매핑 *값*의 위임은 옳다. 그러나 FR-21이 고정한 **구조** — 정확히 4개 입력(성과배수·경쟁공통성·콘텐츠갭·최신성)을 각각 [0,1] 정규화 → 가중합 → ×100 = [0,100] — 은 튜닝값이 아니라 불변식인데 스파인에 고정돼 있지 않다. 또 FR-21 consequence3 *"기회 점수는 성과 배수 하나로 대체되지 않는다"* 가 없다(AD-2의 비합산 규칙은 VPD 대상이지 이게 아니다).

**G7 — FR-2 스코핑 (Low).**
FR-2 *"MVP는 좋아요·댓글수를 수집·저장하되 채점·표시에는 사용하지 않는다(수집만)"* — 조용한 스코핑 결정. AD-9는 like/comment **nil 방어**만 다루고 "수집만, 채점·표시 미사용"은 없다. 데이터 모델 컨벤션에도 없어, 구현자가 채점에 끌어쓸 여지가 남는다.

**기타 경미:**
- FR-10 평면(밴드 없이) 정렬 토글 — 스파인 미언급.
- FR-9 기간 탭 = 업로드 기간 필터(시계열 비의존→콜드스타트 동작)는 능력맵 괄호로만 얇게 포착.
- §11 IA: 좌측 내비 "인기 콘텐츠" = 대시보드 "급상승 영상"과 동일 뷰(별도 기능 아님)라는 중복방지 결정 미반영 — 두 뷰를 각각 만들 위험.

**G4 — 시드 목록 §5 + 카테고리 데이터 홈 (Medium).**
- FR-15 능력맵은 *"channels 컨트롤러 + seed"* 로 **"seed" 단어만** 있고, §5의 4개 카테고리(직접 경쟁 / 한국어 교육 일반 / 언어 교육 참고 / 상단 퍼널)를 초기 추적 채널로 로드한다는 결정·시드 데이터 위치가 Structural Seed에 없다. 초기 부트스트랩의 유일한 출발점인데 실체가 빠졌다.
- 더 실질적으로 — PRD §11/FR-25의 **카테고리·유형 필터 드롭다운(한국어 교육 / 영어 교육 / 일반 영상)** 이 동작하려면 채널(또는 영상)에 category/segment 속성이 필요하다. ERD의 Channel에도, 네이밍/데이터 컨벤션에도 이 속성이 없다. 필터 차원의 데이터 홈이 미정이다. (channel-analysis §5 시드가 바로 이 카테고리 축의 원천이므로 G4는 시드 갭과 한 뿌리다.)

**G1 — §7 다국어 처리 미거버넌스 (Medium-High).**
DESIGN §7은 *"실데이터에서 반드시 터짐"* 이라고 못박은 필수 항목이다 — 폰트 글리프 폴백(KR/JP), `lang="ja"/"ko"` 힌트, `word-break:keep-all`, line-clamp/truncate + `title` 툴팁, `min-w-0`, 긴 일본어 방어. CLAUDE.md 프로젝트 규칙 #4도 이를 강제한다. 그런데 **AD-15는 §10 토큰과 라벨정합만 다루고 §7을 전혀 언급하지 않는다.** 제목·채널명이 들어가는 모든 셀(`shared/_video_row` 등)이 이 처리를 적용해야 한다는 불변식이 없다. 게다가 `lang` 속성 부여는 "각 값의 언어를 무엇이 판정하는가"라는 데이터 책임까지 물고 있는데(자사=ja 확정, 경쟁=혼재 판정 필요) 스파인에 배정처가 없다. 실데이터 100%에서 발생이 보장된 깨짐을 지키는 불변식이 통째로 빠졌다는 점에서 UI 갭 중 가장 심각.

## 권고 (스파인 보강 방향, 값은 건드리지 않음)

1. **AD-15에 §7 다국어 불변식 추가** — 제목·채널명 셀은 §7 처리(폰트폴백·keep-all·truncate+title·min-w-0·lang 힌트)를 강제. lang 판정 책임처(자사 ja 고정 / 경쟁 판정)를 한 줄 명기. (G1)
2. **AD-16(또는 신규 AD)에 추천 정직성 추가** — "자격 <3이면 억지 생성 금지, 'N개 확보' 표시". 별도로 `services/scoring`에 **결정적 동점처리(기회점수→성과배수→최신성)** 불변식. (G2)
3. **AD-15/능력맵 FR-8에 표시 불변식 명문화** — 기본 정렬키=성과배수 내림차순(raw 정렬 금지)·raw 조회수 2차 강등. DESIGN 참조가 아니라 컨트롤러 거동 불변식으로. (G3)
4. **Structural Seed에 시드 채널 로드 + 채널 category 속성** — §5 4카테고리를 초기 추적 채널 seed로, Channel에 category/segment 컬럼(필터 드롭다운 데이터 홈). (G4)
5. **AD-16/AD-2에 FR-24 기전(2) 명명** — 최근 N 기준선이 오래된 영상 배수를 추가 증폭, 에버그린 후보가 이를 상속. 안내가 (1)만 탓하지 않도록. (G5)
6. **AD-2 또는 AD-4에 기회점수 구조 고정** — 4입력→[0,1]→가중합→×100, 성과배수로 대체 불가(값·가중치는 config 유지). (G6)
7. **AD-9/컨벤션에 FR-2 스코핑 한 줄** — like/comment는 수집·저장만, 채점·표시 미사용. (G7)
