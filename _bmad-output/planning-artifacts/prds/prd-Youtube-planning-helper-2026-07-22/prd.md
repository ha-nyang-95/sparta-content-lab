## 1. Vision

일본인에게 일본어로 한국어를 가르치는 유튜브 채널(구독자 약 1만, @KankokugoBenkyo / SPARTA)의 **내부용 콘텐츠 리서치 대시보드**다. 운영자가 매주 4~5시간씩 손으로 하던 유튜브 주제 조사 — 경쟁·인접 채널을 검색하고, 조회수와 구독자를 비교하고, 이미 만든 주제인지 확인하는 일 — 을 **10분 이내**로 줄인다.

핵심은 데이터 수집이 아니라 **"좋은 영상"을 판정하는 채점 방법론**이다. 단순 조회수는 규모 큰 채널에 유리하므로, 각 채널을 **자기 자신과 비교**하는 성과 배수(채널 내부 중앙값 대비 배수, vidIQ·Viewstats가 독립 채택한 업계 방식)를 핵심 지표로 삼는다. 이 방식은 비교군을 일본어권 한국어 교육이라는 극소 니치를 넘어 영어권 한국어 교육·언어 교육 일반까지 넓혀도 카테고리 간 규모 차가 상쇄되어 성립한다.

최종 산출물은 화면 가득한 데이터가 아니라 **다음 주에 제작할 영상 주제 3개를, 데이터 근거와 참고 영상과 함께** 빠르게 결정하도록 돕는 것이다. 사용자는 운영자 본인과 동료 1명, 총 2명이며 주 1회 사용한다.

## 2. Target User

### 2.1 Jobs To Be Done

- **기능적** — 매주 다음 제작 주제 3개를 데이터 근거와 함께 10분 안에 결정한다.
- **기능적** — 규모가 다른 경쟁·인접 채널의 콘텐츠 성과를 공정하게 비교한다(대형 채널 편향 제거).
- **기능적** — 최근 인기 콘텐츠와 에버그린 콘텐츠를 구분해 찾는다.
- **기능적** — 후보 주제를 자사 채널에서 이미 다뤘는지 즉시 확인한다.
- **정서적** — 주관적 감·기억·검색어 운에 의존하던 조사를 시장에서 검증된 기준으로 대체해 결정에 확신을 갖는다.
- **맥락적** — 다른 프로젝트와 병행하는 상황에서 조사에 쓰는 시간을 최소화한다.

### 2.2 Non-Users (v1)

- 외부 고객·구독자. 이 도구는 대외 공개용이 아니라 내부 업무용이다.
- 콘텐츠 제작·업로드 자동화를 원하는 사용자. 이 도구는 **조사만** 하고 제작·업로드는 사람이 한다.
- SPARTA 외 타 채널 운영자. v1은 이 채널 운영 팀(2인) 전용이다.

### 2.3 Key User Journeys

내부 단일 운영자 역할이므로 여정은 경량으로 둔다. 주인공은 운영자 **Hwan**이다.

- **UJ-1. Hwan이 월요일 아침 10분 만에 이번 주 주제를 결정한다.**
  - **페르소나·맥락** — Hwan은 SPARTA 채널 운영자로, 다른 프로젝트와 병행하며 주 1회 콘텐츠를 기획한다.
  - **진입 상태** — PC 브라우저로 대시보드에 접속(내부 도구, 로그인은 최소). 수집 스케줄러가 밤사이 데이터를 갱신해 둔 상태.
  - **경로** — (1) 상단 "이번 주 추천 콘텐츠 3개" 카드에서 추천 주제·기회 점수·근거를 훑는다. (2) 각 카드의 "근거 보기"로 참고 경쟁 영상(성과 배수·조회수·URL)과 자사 유사영상 유무를 확인한다. (3) 급상승 영상 테이블에서 성과 배수 높은 영상을 살펴본다. (4) 마음에 드는 영상을 저장한다.
  - **절정** — 데이터 근거를 갖춘 주제 3개를 확정한다. 손으로 4~5시간 하던 일이 10분 안에 끝난다.
  - **해소** — 저장한 영상·주제를 참고해 다음 제작에 들어간다.
  - **엣지 케이스** — 콜드 스타트 기간(수집 시작 직후)에는 시계열 의존 위젯이 "데이터 수집 중"으로 표시되고, 1일차 동작 지표(성과 배수·에버그린 후보·콘텐츠 갭)만으로도 추천이 산출된다.

- **UJ-2. Hwan이 새로 발견한 경쟁 채널을 직접 등록한다.**
  - Hwan은 자동 추천된 경쟁 채널 목록을 보다가 시스템이 놓친 채널을 발견하고, 채널 URL을 입력해 추적 대상에 추가한다. 다음 수집 주기부터 그 채널 영상이 대시보드에 반영된다. 관련 없는 채널은 제외한다.

## 3. Glossary

다운스트림 워크플로와 화면 문구는 아래 용어를 그대로 쓴다. 동의어를 새로 만들지 않는다.

- **성과 배수 (Outlier / Performance Multiple)** — 한 영상의 조회수 ÷ 그 영상이 속한 **채널·영상 유형(쇼츠 또는 롱폼)의 기준선**. 이 도구의 핵심 성과 지표다. UI·문서 전체에서 "구독자 대비 조회수"가 아니라 이 용어를 쓴다.
- **기준선 (Baseline)** — 한 채널의 특정 영상 유형에서 최근 N개 공개 영상 조회수의 **중앙값(median)**. 평균이 아니다. 채널·유형마다 독립 계산된다.
- **중앙값 (Median)** — 기준선 산출에 쓰는 대표값. 소수 대박 영상이 기준선을 오염시키는 것을 막기 위해 평균 대신 채택.
- **영상 유형 (Video Type)** — 쇼츠(Shorts) 또는 롱폼(Long-form). 기준선·필터·표시에서 절대 섞지 않는다.
- **회원 전용 영상 (Members-only Video)** — 공개 조회수가 가려진 영상. 기준선 표본과 성과 비교에서 제외한다.
- **VPD (Views Per Day, 일간 조회수 증분)** — 하루 사이 조회수 델타. 모멘텀(상승세) 축이며 성과 배수와 별개다. 스냅샷 축적이 전제라 콜드 스타트 이후 동작한다.
- **에버그린 후보 (Evergreen Candidate)** — 업로드된 지 오래됐는데 현재 조회수가 채널 기준선을 넘는 영상. 대리지표라 1일차부터 표시하되 "후보"로 라벨링한다.
- **에버그린 (Evergreen, 검증)** — 일일 스냅샷의 나이 대비 조회수 증분 곡선이 낮고 평탄한 지속형으로 확인된 영상. 스냅샷 2~3주 축적 후 "후보"에서 승격된다.
- **스냅샷 (Snapshot)** — 영상·채널의 일별 조회수·구독자 관측 1행. 시계열 지표(VPD·에버그린 승격·구독자 증감)의 원천.
- **기회 점수 (Opportunity Score)** — 추천 주제 랭킹용 종합 점수(0~100). 벤더가 공개 산식을 제공하지 않는 우리 자체 지표로, 성과 배수 신호·경쟁 공통성·콘텐츠 갭·최신성을 가중 합산한다.
- **콘텐츠 갭 (Content Gap)** — 경쟁 영상 주제 대비 자사 채널이 그 주제를 다루지 않았거나(미제작), 다뤘어도 오래된 정도. 미제작 / 유사영상 1개 / 유사영상 2개+ / 포화의 4구간으로 분류한다.
- **자사 유사영상 (Similar Own Video)** — 임베딩 유사도로 판정한, 경쟁 영상과 주제가 가까운 자사 영상. 코스(회원 전용) 영상은 제목·주제 매칭까지만 되고 성과 비교는 불가하다.
- **구독자 밴드 (Subscriber Band)** — 채널을 구독자 규모로 나눈 티어(<1만 / 1만~10만 / 10만~50만 / 50만+). 성과 배수의 분모가 아니라 필터·그룹핑 축이다.
- **신뢰도 하한 (Confidence Floor)** — 기준선 계산에 쓸 유형별 최근 공개 영상이 10개 미만이면 붙는 저신뢰 플래그.
- **절대조회수 하한 (Absolute View Floor)** — 소표본 플루크(예: 40뷰의 50배)를 거르는 최소 조회수 필터(기본 1,000~5,000).
- **추적 채널 (Tracked Channel)** — 수집·채점 대상 채널. 자사 채널 + 시스템 자동 추천 + 사용자 수동 등록으로 구성된다.
- **콜드 스타트 (Cold Start)** — 스냅샷이 아직 얇아 시계열 지표를 신뢰할 수 없는 수집 초기 기간.

## 4. Features

각 하위 절은 하나의 기능이며, 행위 서술 뒤에 FR을 전역 번호로 중첩한다. FR은 재구성돼도 안정적으로 참조되도록 FR-1..FR-N으로 전역 번호를 유지한다.

### 4.1 데이터 수집·갱신 파이프라인

**설명.** 추적 채널의 영상 메타·조회수·구독자를 YouTube Data API v3로 하루 1회 자동 수집하고, 일별 스냅샷을 축적한다. 운영자가 겪은 "로컬이라 컴퓨터 꺼지면 수집 끊김"과 "스크래핑 IP 차단" 문제를 정식 API + 상시 실행 스케줄러로 해소한다. 영상 열거는 `search.list`(하루 100콜 별도 버킷)가 아니라 uploads 플레이리스트 경유(`channels.list` → `playlistItems.list` → `videos.list`, 각 콜당 1 unit)로 한다. 신규 채널·경쟁 영상 발굴은 `search.list`를 주 1회 배치로 몬다. 이 기능은 §9 기술 제약의 대부분을 실현하는 백본이다.

**Functional Requirements:**

#### FR-1: 일 1회 자동 수집

시스템은 상시 실행 스케줄러로 추적 채널의 영상 통계를 하루 1회 자동 갱신한다. 실현 UJ-1.

**Consequences (testable):**
- 스케줄러 프로세스가 상시 떠 있고, 서버 재시작 후에도 스케줄·잡 상태가 지속된다(DB 저장).
- 하루 1회 갱신이 최소 보장이며, 갱신 실패 시 지수 백오프로 재시도한다.
- 갱신 주기 상한은 하루 1회다(과잉 호출로 레이트리밋을 유발하지 않는다).

#### FR-2: uploads 플레이리스트 경유 영상 열거

시스템은 `channels.list`로 각 채널의 uploads 플레이리스트 ID와 구독자 수를 얻고, `playlistItems.list`로 영상 ID를, `videos.list`로 조회수·좋아요·댓글·길이·제목·썸네일·업로드일을 배치(최대 50)로 수집한다.

**Consequences (testable):**
- `videos.list` 한 콜로 최대 50개 영상의 필요한 필드가 모두 반환된다(part 개수와 무관하게 콜당 1 unit).
- `likeCount`/`commentCount`가 응답에서 누락돼도(크리에이터가 숨김) nil로 방어되어 파이프라인이 중단되지 않는다.
- `contentDetails.duration`(ISO 8601)이 정상 파싱된다.

#### FR-3: 일별 스냅샷 축적

시스템은 수집한 영상 조회수와 채널 구독자를 일별 스냅샷으로 저장해 시계열 지표(VPD·에버그린 승격·구독자 증감)의 원천으로 삼는다.

**Consequences (testable):**
- `(video_id, date)` 조합이 유니크해 같은 날 중복 행이 생기지 않는다.
- 스냅샷은 수집 1일차부터 쌓이며, 시계열 지표는 스냅샷이 충분히 쌓인 뒤 값이 나온다.
- 최근 90일은 일단위로 유지하고, 이후는 주단위 집계로 롤업 후 원본을 삭제한다.

#### FR-4: 신규 채널·경쟁 영상 발굴

시스템은 `search.list`를 주 1회 배치로 사용해 키워드 기반 신규 채널·경쟁 영상 후보를 발굴한다.

**Consequences (testable):**
- 발굴 배치는 `search.list` 하루 100콜 상한 안에서 동작한다.
- 발굴은 채점 파이프라인(일 1회 갱신)과 분리된 주기(주 1회)로 돈다.

**Feature-specific NFRs:**
- MVP 현실치(50채널 × 200영상 = 1만 영상)에서 일일 쿼터 사용은 기본 1만 units의 3% 미만이어야 한다.

### 4.2 성과 배수 스코어링 엔진

**설명.** 이 프로젝트의 진짜 핵심이다. 각 영상의 성과 배수 = 조회수 ÷ 그 채널·유형의 기준선(중앙값)으로 계산한다. 조회수÷구독자 방식은 자사 실측에서 왜곡이 확인되어 폐기했다(공개 조회수 200~4,100 대 구독자 10,200, 비율 전부 1 미만). 평균이 아니라 중앙값을 쓰고(자사 롱폼 평균/중앙값 3.9배), 쇼츠/롱폼 기준선을 분리하며(자사 쇼츠 중앙값이 롱폼의 2.7배), 회원 전용 영상을 표본에서 뺀다. 성과(배수)와 모멘텀(VPD)은 하나로 뭉치지 않는다.

**Functional Requirements:**

#### FR-5: 성과 배수 계산

시스템은 각 영상의 성과 배수를 (조회수 ÷ 채널·유형별 기준선)으로 계산한다. 실현 UJ-1.

**Consequences (testable):**
- 기준선은 **평균이 아니라 중앙값**이다.
- 기준선은 채널마다, 그리고 쇼츠/롱폼 유형마다 **독립 계산**된다(둘의 기준선을 절대 공유하지 않는다).
- 회원 전용 영상(조회수 nil/0)은 기준선 표본과 성과 비교에서 제외된다.
- 기준선 표본은 채널·유형별 최근 N개 공개 영상이며 N은 튜닝 가능하다 `[ASSUMPTION: 얇은 표본 방어 위해 기본 N=20~30, 본개발 실측 튜닝]`.
- MVP에서 성과 배수는 **현재 누적 조회수** 기준으로 계산되며, 오래된 영상이 유리해지는 시점 정합 편향은 UI에 명시된다(FR-24).

#### FR-6: 신뢰도·플루크 방어

시스템은 소표본·소형 채널에서의 오탐을 방어하는 플래그·필터를 제공한다.

**Consequences (testable):**
- 유형별 최근 공개 영상이 10개 미만인 채널의 기준선에는 신뢰도 하한 플래그가 붙는다.
- 절대조회수 하한(기본 1,000~5,000) 미만 영상은 성과 배수 순위에서 기본 제외된다.
- 성과 배수가 25배를 초과하면 "검증 요망 — 외부 요인 가능" 플래그가 붙는다.

#### FR-7: 성과와 모멘텀 축 분리

시스템은 성과 배수(성과)와 VPD(모멘텀)를 별도 축으로 유지한다.

**Consequences (testable):**
- 성과 배수와 VPD를 하나의 종합 점수로 합산하지 않는다.
- VPD는 스냅샷 축적 전(콜드 스타트)에는 값 대신 "수집 중" 상태로 표시된다(FR-23).

### 4.3 통합 대시보드 & 기간 전환

**설명.** 등록된 자사·경쟁 채널 영상을 한 화면에서 본다. 상단에 "이번 주 추천 콘텐츠 3개"가 오고, 기간 탭(최근 1주 / 1개월 / 3개월 / 에버그린)으로 전환한다. 목업 레이아웃을 유지하되, "구독자 대비 조회수" 라벨은 전부 "성과 배수(채널 평소 대비)"로 통일한다. 상단 우측에 카테고리·유형 필터 드롭다운(한국어 교육 / 영어 교육 / 일반 영상 + Shorts)을 둔다.

**Functional Requirements:**

#### FR-8: 통합 대시보드 뷰

시스템은 추적 채널의 영상을 성과 배수 기준으로 정렬한 통합 대시보드를 한 화면에 제공한다. 실현 UJ-1.

**Consequences (testable):**
- 기본 정렬은 성과 배수 내림차순이다(raw 조회수 기본 정렬 금지).
- 성과 배수가 히어로 셀로 가장 크게·볼드·색상 밴드(<2배 중립 / 2~5배 / 5~10배 / >10배)로 표시되고 raw 조회수는 2차 컬럼으로 강등된다.
- 화면 문구 어디에도 "구독자 대비 조회수" 표현이 없고 "성과 배수(채널 평소 대비)"로 통일된다.

#### FR-9: 기간 전환

시스템은 최근 1주 / 1개월 / 3개월 기간 탭과 에버그린 탭으로 뷰를 전환한다.

**Consequences (testable):**
- 기간 탭은 **업로드 기간 필터**로 동작한다(해당 기간 내 업로드된 영상을 대상으로 성과 배수 정렬). 시계열 트렌드 계산에 의존하지 않아 콜드 스타트에서도 동작한다.
- 에버그린 탭은 §4.5의 에버그린 후보/에버그린을 보여준다.

#### FR-10: 구독자 밴드 티어링

시스템은 결과를 구독자 밴드(<1만 / 1만~10만 / 10만~50만 / 50만+)로 그룹핑하고, 밴드 내에서 성과 배수로 정렬한다.

**Consequences (testable):**
- 기본 그룹핑이 구독자 밴드 티어이며, 밴드 내 정렬로 소형 채널의 대박이 자기 슬롯에서 드러난다.
- 평면(밴드 없이 전체) 정렬로 토글할 수 있다.

### 4.4 급상승 영상

**설명.** 목업의 "급상승 영상" 테이블이다. 컬럼은 순번 / 영상(썸네일+제목) / 채널 / 업로드일 / 조회수 / 성과 배수(채널 평소 대비) / 트렌드(최근 7일 스파크라인) / 자사 유사영상이다.

**Functional Requirements:**

#### FR-11: 급상승 영상 테이블

시스템은 성과 배수 상위 영상을 테이블로 표시하며 각 행에 썸네일·제목·채널·업로드일·조회수·성과 배수·자사 유사영상 유무를 담는다. 실현 UJ-1.

**Consequences (testable):**
- 각 행의 성과 배수는 색상 밴드로 강조되고 raw 조회수는 뮤트 컬럼이다.
- 자사 유사영상 유무(없음 / N개)가 각 행에 표시된다(FR-17).
- 영상 클릭 시 유튜브 URL로 이동 가능하다.

#### FR-12: 트렌드 스파크라인 (시계열, 콜드 스타트 조건부)

시스템은 각 영상의 최근 7일 조회수 추세를 스파크라인으로 표시한다.

**Consequences (testable):**
- 스파크라인은 스냅샷 시계열에 의존하며, 콜드 스타트에는 "데이터 수집 중" 플레이스홀더로 표시된다(FR-23).
- 목업의 트렌드 컬럼 자리는 MVP에서 유지되고 값만 수집 후 채워진다.

### 4.5 에버그린 콘텐츠

**설명.** 최근 인기와 구분되는, 오래돼도 꾸준히 조회되는 검색 유입형 주제다. (A)스냅샷 승격 + (B)대리지표 즉시노출 혼합으로 간다. 벤더에 검증된 에버그린 지표가 없어 우리가 설계한 축이다.

**Functional Requirements:**

#### FR-13: 에버그린 후보 즉시 노출 (대리지표)

시스템은 "업로드된 지 오래됐는데 현재 조회수가 채널 기준선을 넘는 영상"을 에버그린 후보로 1일차부터 표시한다. 실현 UJ-1.

**Consequences (testable):**
- 이 영상들은 "에버그린 후보"로 라벨링되며 "에버그린"으로 단정하지 않는다(급등 후 식은 영상과 아직 구분 불가).
- 후보 판정은 스냅샷 없이 현재 조회수·업로드일·기준선만으로 계산된다(1일차 동작).

#### FR-14: 에버그린 승격 (검증, 콜드 스타트 이후)

시스템은 일일 스냅샷의 나이 대비 조회수 증분 곡선이 낮고 평탄한 지속형인 영상을 검증된 에버그린으로 승격한다.

**Consequences (testable):**
- 승격은 스냅샷이 충분히 쌓인 뒤(수 주) 동작하며, 그 전에는 "데이터 수집 중" 상태다.
- 승격된 에버그린은 후보와 시각적으로 구분된다.

### 4.6 경쟁 채널 관리

**설명.** 관련성 높은 경쟁 채널을 시스템이 자동 추천하고, 사용자가 URL로 직접 추가·제외한다. `channel-analysis.md` §5의 4개 카테고리(직접 경쟁 / 한국어 교육 일반 / 언어 교육 참고 / 한국 관련 상단 퍼널) 시드 목록을 초기 출발점으로 쓴다.

**Functional Requirements:**

#### FR-15: 경쟁 채널 자동 추천 + 수동 등록/제외

시스템은 경쟁 채널을 자동 추천하고, 사용자가 채널 URL로 추가하거나 목록에서 제외할 수 있다. 실현 UJ-2.

**Consequences (testable):**
- 사용자가 채널 URL을 입력하면 다음 수집 주기부터 그 채널이 추적 대상에 포함된다.
- 사용자가 제외한 채널은 대시보드·채점에서 빠진다.
- 시드 목록(channel-analysis §5)이 초기 추적 채널로 로드된다.

#### FR-16: 경쟁 채널 동향

시스템은 추적 채널의 채널명·구독자·(조건부)구독자 증감을 요약 목록으로 보여준다.

**Consequences (testable):**
- 목업의 "경쟁 채널 동향" 위젯이 채널명·구독자 수·구독자 증감(FR-18)을 표시한다.

### 4.7 자사 유사영상 & 콘텐츠 갭

**설명.** 경쟁 영상 주제를 자사 채널이 이미 다뤘는지 임베딩 유사도로 판정한다. gemini-embedding-001(유료 결제)로 제목(+설명) 임베딩을 만들고, BLOB 저장 + Ruby 코사인으로 유사도를 계산한다. 자사 코스(회원 전용) 영상은 제목·주제 매칭까지만 되고 성과 비교는 불가하다 — 이건 API가 회원 영상 통계를 주지 않아 **강제되는 명시적 한계**다.

**Functional Requirements:**

#### FR-17: 자사 유사영상 판정

시스템은 경쟁 영상마다 주제가 가까운 자사 영상이 있는지 임베딩 유사도로 판정하고, 있으면 제목·썸네일·URL을 보여준다. 실현 UJ-1.

**Consequences (testable):**
- 임베딩은 영상당 1회만 생성된다(제목 불변).
- 유사도 임계값은 알려진 중복/비중복 제목 쌍으로 실측 튜닝하며 고정 0.8을 맹신하지 않는다.
- 코스(회원 전용) 자사 영상은 제목·주제 매칭 결과에는 나오되 성과 비교 수치는 표시되지 않는다.

#### FR-18: 콘텐츠 갭 분포

시스템은 경쟁 영상 주제 대비 자사 커버리지를 미제작 / 유사영상 1개 / 유사영상 2개+ / 포화의 4구간으로 분류해 분포를 보여준다.

**Consequences (testable):**
- 목업의 "콘텐츠 기회" 도넛이 4구간 비율·건수를 표시한다.
- 각 급상승 영상 행의 자사 유사영상 컬럼과 분류가 일치한다.

### 4.8 다음 주 추천 주제 3개

**설명.** MVP의 최종 산출물이다. 조사 결과를 바탕으로 다음 주 제작할 주제 3개를 기회 점수·근거·참고 경쟁 영상과 함께 추천한다. 주제 묶기는 §4.7의 임베딩을 재사용한 자동 묶기로 한다(일·한 교차 묶기, 추가 비용 ~0). 기회 점수는 벤더가 공개 산식을 제공하지 않는 우리 자체 종합 점수다.

**Functional Requirements:**

#### FR-19: 추천 주제 3개 산출

시스템은 다음 주 제작 우선순위로 주제 3개를 기회 점수와 함께 제시한다. 실현 UJ-1.

**Consequences (testable):**
- 각 추천은 주제명뿐 아니라 추천 이유와 참고 경쟁 영상(제목·썸네일·채널·조회수·URL)을 포함한다.
- 각 카드에 경쟁 영상 상승 개수·성과 배수·자사 유사영상 유무·기회 점수(0~100)가 표시된다.
- "근거 보기"로 참고 영상 상세를 펼칠 수 있다.

#### FR-20: 임베딩 기반 주제 자동 묶기

시스템은 §4.7과 같은 임베딩을 재사용해 영상을 주제 단위로 자동 묶는다.

**Consequences (testable):**
- 주제 묶기는 스냅샷이 아니라 임베딩에 의존해 1일차부터 동작한다.
- 묶기는 유사영상 판정과 같은 임베딩 인프라를 재사용해 추가 임베딩 비용이 발생하지 않는다.
- `relatedToVideoId`(폐기됨)에 의존하지 않는다.

#### FR-21: 기회 점수 산출

시스템은 성과 배수 신호·경쟁 공통성·콘텐츠 갭·최신성을 가중 합산한 기회 점수(0~100)로 주제를 랭킹한다.

**Consequences (testable):**
- 기회 점수 구성 요소는 문서화되고 가중치는 튜닝 가능하다 `[ASSUMPTION: 4개 요소의 초기 가중치는 본개발 때 실데이터로 정한다]`.
- 기회 점수는 성과 배수와 별개의 종합 지표이며, 성과 배수 하나로 대체되지 않는다.

**Notes:** `[NOTE FOR PM: 기회 점수는 시장에 공개 산식이 없는 우리 자체 지표다. 초기엔 투명한 가중합으로 두고, 사용자 피드백으로 가중치를 조정한다.]`

### 4.9 구독자 증감 (규모 조건부)

**설명.** 목업의 "구독자 증가(최근 7일) +1.8만"이다. 구독자 시계열은 API에 없어 오늘부터 스냅샷을 쌓아야 하고, 값이 3자리로 반올림되어 소형 채널의 주간 증감은 노이즈에 묻힌다. 그래서 규모 임계 이상 채널만 표시하고 소형은 "측정한계"로 둔다. 스냅샷은 FR-2의 `channels.list`에 동승해 추가 API 비용이 0이다.

**Functional Requirements:**

#### FR-22: 조건부 구독자 증감 표시

시스템은 7일 스냅샷이 쌓인 뒤, 규모 임계 이상 채널에만 구독자 증감을 표시하고 그 미만은 "측정한계" 라벨을 붙인다.

**Consequences (testable):**
- 규모 임계 미만 채널에는 증감 수치 대신 "측정한계" 라벨이 표시된다 `[ASSUMPTION: 임계 기준 예시는 구독자 10만+, 본개발 때 확정]`.
- 증감은 추적 시작 이후 스냅샷으로만 계산되며 소급 표시하지 않는다.
- 구독자 스냅샷 수집에 별도 API 콜 비용이 들지 않는다(channels.list 동승).

### 4.10 콜드 스타트 상태 처리

**설명.** 스냅샷이 얇은 초기 며칠간, 1일차 동작 지표로 화면을 채우고 시계열 의존 축만 "데이터 수집 중"으로 둔다.

**Functional Requirements:**

#### FR-23: 콜드 스타트 상태 표시

시스템은 시계열 의존 위젯(트렌드 스파크라인·VPD 급상승·검증 에버그린·구독자 증감)을 스냅샷이 충분히 쌓이기 전까지 "D+n 데이터 수집 중" 플레이스홀더로 표시한다.

**Consequences (testable):**
- 1일차 동작 지표(성과 배수·에버그린 후보·콘텐츠 갭·추천 주제 3개)는 콜드 스타트에도 정상 표시된다.
- 각 시계열 위젯은 어느 축이 준비됐고 어느 축이 수집 중인지 개별적으로 구분해 표시한다(전역 배너 하나로 뭉개지 않는다).

#### FR-24: 시점 정합 편향 명시

시스템은 성과 배수가 현재 누적 조회수 기준임을 UI에 명시해 오래된 영상이 유리해지는 편향을 사용자가 인지하게 한다.

**Consequences (testable):**
- 각 영상에 업로드일이 표시되고, 성과 배수 옆(또는 툴팁)에 누적 조회수 기준·편향 가능 안내가 있다.

### 4.11 검색·필터·정렬

**설명.** 키워드·채널·영상 유형·업로드 기간·조회수·성과 배수·구독자 규모로 영상을 검색·정렬한다.

**Functional Requirements:**

#### FR-25: 검색·필터·정렬

시스템은 키워드·채널·영상 유형·업로드 기간·조회수·성과 배수·구독자 밴드 기준으로 영상을 검색·필터·정렬한다.

**Consequences (testable):**
- 구독자 밴드 필터와 성과 배수 임계 프리셋(2x/3x/5x/10x/25x)을 제공한다.
- 쇼츠/롱폼은 필터 차원에서 분리 유지된다.

#### FR-26: 영상 저장

시스템은 사용자가 관심 영상을 저장 목록에 담을 수 있게 한다. 실현 UJ-1.

**Consequences (testable):**
- 저장한 영상은 "저장한 영상" 화면에서 다시 볼 수 있다.

## 5. Non-Goals (Explicit)

- **콘텐츠 제작·업로드 자동화 아님.** 이 도구는 조사만 한다. 제작·업로드는 사람이 한다.
- **절대 검색량(수요) 제공 아님.** YouTube가 검색량을 주지 않아 상용 서비스도 전부 추정치다. 이 니치에서는 clickstream 표본이 희박해 신뢰구간이 무너진다. 절대치는 포기하고 공급측 신호로 대체한다.
- **vidIQ/Viewstats의 복제 아님.** 같은 설계 철학의 독자 구현이지 산식 복제가 아니다(벤더는 정확한 수식을 공개하지 않았다).
- **대외 공개 서비스 아님.** 내부 2인 전용 도구다. 멀티테넌시·과금·외부 회원 관리는 v1 대상이 아니다.
- **자사 회원 전용 영상의 성과 분석 아님.** API가 통계를 주지 않아 불가능하다(제목·주제 매칭까지만).
- **실시간(시간 단위) 지표 아님.** 갱신은 하루 1회 상한이라 VPH가 아니라 VPD를 쓴다.

## 6. MVP Scope

### 6.1 In Scope

- 통합 대시보드(자사+경쟁 채널 한 화면), 기간 탭(1주/1개월/3개월/에버그린)
- 성과 배수 스코어링(채널 내부 중앙값, 쇼츠/롱폼 분리, 회원 전용 제외, 현재 누적 조회수 + 편향 명시)
- 신뢰도 하한·절대조회수 하한·극단배수(>25x) 플래그, 구독자 밴드 티어링
- 급상승 영상 테이블(성과 배수 정렬, 자사 유사영상 유무)
- 에버그린 후보(대리지표, 1일차 동작)
- 콘텐츠 갭 분포 + 자사 유사영상 판정(gemini 임베딩, 코스=제목 매칭만)
- 다음 주 추천 주제 3개(기회 점수·근거·참고 영상) + 임베딩 재사용 자동 주제 묶기
- 경쟁 채널 자동 추천 시드 + 수동 추가/제외
- 검색·필터·정렬, 영상 저장
- 일 1회 자동 수집(Solid Queue recurring + SQLite WAL, 상시 스케줄러) + 1일차부터 스냅샷 축적
- 반응형(PC 중심, 모바일 화면 안 깨짐)
- 구독자 증감 — 규모 임계 이상 채널만(7일 후), 소형은 "측정한계"
- 쇼츠/롱폼 판별 — duration 휴리스틱만, `is_short` DB 캐시

**MVP In이되 값은 "수집 중" 자리만**
- 트렌드 스파크라인 / VPD 급상승 지표 — 목업 자리 유지, 값은 D+n

### 6.2 Out of Scope for MVP

- VPD 신뢰값·검증된 에버그린 승격(감쇠 기울기) — 스냅샷 2~3주 축적 필요.
- 구독자 증감 소형 채널 — 3자리 반올림 노이즈로 사실상 측정 불가.
- `/shorts` HTTP 프로브 쇼츠 판별 보정 — IP 차단 위험, 저속·캐시 필요. `[NOTE FOR PM: duration 경계 오분류율이 실데이터에서 높게 나오면 post-MVP 1순위로 당긴다.]`
- 나이 정합(시점 정합) 배수 — 과거 조회수 시계열 소급 불가.
- 키워드 채점 축(수요/공급 경쟁 신호)을 별도 점수 UI로 — MVP는 영상 채점·추천에 집중.
- 카테고리별 인기 순위(미팅 §4 개발자 nice-to-have).
- sqlite-vec 벡터 검색 — N≈500엔 Ruby 코사인으로 충분, 벡터 5만 초과 시 전환.

## 7. Success Metrics

planning.md §10의 7개 성공 기준을 검증 가능한 형태로 옮긴다.

**Primary**
- **SM-1: 조사 시간 단축** — 운영자가 주간 주제 조사를 착수부터 주제 3개 확정까지 **10분 이내**에 끝낸다. 검증 FR-8·FR-11·FR-19. 측정 = 사용자 관찰/타임박스 테스트.
- **SM-2: 근거 있는 주제 3개** — 매주 데이터 근거(성과 배수·참고 영상·자사 유사영상)를 갖춘 주제 3개가 산출된다. 검증 FR-19·FR-21.

**Secondary**
- **SM-3: 인기 vs 에버그린 구분** — 사용자가 최근 인기 콘텐츠와 에버그린(후보)을 화면에서 구분해 찾을 수 있다. 검증 FR-9·FR-13.
- **SM-4: 경쟁 채널 관리** — 사용자가 경쟁 채널을 자동 추천받거나 URL로 직접 등록/제외할 수 있다. 검증 FR-15.
- **SM-5: 규모 공정 비교** — 구독자 규모가 다른 채널의 성과를 성과 배수로 공정하게 비교할 수 있다. 검증 FR-5·FR-10.
- **SM-6: 자사 중복 확인** — 후보 주제가 자사에서 이미 다룬 것인지 확인할 수 있다. 검증 FR-17·FR-18.
- **SM-7: 무학습 사용성** — 운영자와 동료가 별도 교육 없이 화면을 이해하고 사용한다(첫 사용 시 도움 요청 없이 주제 3개 도달). 검증 FR-8.

**Counter-metrics (do not optimize)**
- **SM-C1: 화면 데이터 밀도** — "더 많은 데이터"를 목표로 삼지 않는다. 주제 3개 결정 속도가 정보량보다 우선한다. SM-1을 반균형.
- **SM-C2: 성과 배수 과신** — 극단 배수(>25x)나 소표본 플루크를 무비판적으로 상위 노출하지 않는다. 신뢰도·절대값 하한이 이를 억제한다. SM-2·SM-5를 반균형.

## 8. Cross-Cutting NFRs

- **수집 지속성** — 스케줄러는 상시 실행이며 서버 재시작 후에도 스케줄·잡 상태가 지속된다(로컬 중단 문제 해소).
- **동시성** — SQLite WAL(Rails 8 기본) + busy_timeout 5000ms로 배치 쓰기 중 웹 읽기가 논블로킹으로 동작한다. 단일 라이터이므로 배치 트랜잭션을 짧게 유지하고 Solid Queue/Cache는 별도 DB 파일로 분리한다.
- **레이트리밋 내성** — 정식 API 실패(403 quota/rate)는 지수 백오프로 재시도한다. 스크래핑성 IP 차단은 `/shorts` 프로브(post-MVP)를 제외하면 발생하지 않는다.
- **성능(체감)** — 대시보드 첫 화면·정렬·필터 전환이 주 1회 내부 사용에 불편 없는 응답성을 갖는다. 유사도 계산·수집은 배치라 웹 요청 경로에서 제외된다.
- **가용성 기대치** — 내부 2인·주 1회 도구라 고가용성은 요구되지 않는다. 수집 1일 실패는 다음 주기 복구로 허용된다.
- **관측성** — 수집 잡의 성공/실패/재시도 이력이 DB에 남아 확인 가능하다.
- **정직성(UI)** — 콜드 스타트, 시점 정합 편향, 구독자 반올림 한계, 에버그린 후보/검증 구분을 화면에 정직하게 표시한다(불확실성을 숨기지 않는다).

## 9. Constraints & Guardrails

### 9.1 기술 제약 (기술 실현성 조사 §9의 10개 항목)

1. **쿼터** — Data API 기본 1만 units/day. `videos.list`·`channels.list`·`playlistItems.list`는 각 콜당 1 unit(part 무관). 영상 열거는 uploads 플레이리스트 경유(배치 50). `search.list`는 별도 버킷 하루 100콜 상한 → 발굴은 주 1회 배치.
2. **쇼츠 판별 불완전** — API에 `isShort` 필드 없음. MVP는 duration 휴리스틱, 판별 결과 `is_short`를 영상당 1회 DB 캐시. `/shorts` 프로브 보정은 post-MVP(저속·캐시 필수, 대량 고속 = IP 차단). 쇼츠/롱폼 기준선·필터 완전 분리.
3. **회원 전용 영상** — API가 통계 미제공 → 기준선 표본에서 제외(nil 방어). 자사 자기 데이터는 별도 YouTube Analytics API 영역(v1 미사용).
4. **구독자 증감** — 시계열 API 없음(오늘부터 스냅샷), 값 3자리 반올림 → 소형 채널 주간 증감은 노이즈. 소형 채널 UI에 "측정한계" 표시. 추가 API 비용 0(channels.list 동승).
5. **시점 정합 소급 불가** — 추적 이전 영상은 "영상 나이 t일 시점 조회수"를 만들 수 없음. MVP는 현재 누적 조회수 기준 + 편향 UI 명시.
6. **스택** — Solid Queue 반복작업(`config/recurring.yml`) + SQLite, Redis 불필요. 스케줄러 프로세스 상시 실행 필수. SQLite WAL(Rails 8 기본) + busy_timeout 5000ms, 단일 라이터(배치 트랜잭션 짧게), Solid Queue/Cache는 별도 DB 파일.
7. **스냅샷 테이블** — `(video_id, date)` 유니크 인덱스, 90일 일단위 후 주단위 롤업 + `VACUUM`. 행 수는 SQLite 한계 대비 무시 가능(~365만 행/년, 1~2GB).
8. **유사영상/주제 묶기** — 임베딩은 `gemini-embedding-001` **유료 결제**로 사용(무료 티어 축소 중이라 의존 금지, YouTube와 같은 Google 계정·다른 키). 저장은 BLOB + Ruby 코사인(DB는 SQLite 그대로, 네이티브 확장 불필요), 벡터 5만 초과 시 sqlite-vec 전환. 임계값 실측 튜닝. `relatedToVideoId` 폐기라 관련영상 API 없음.
9. **표시** — 기본 정렬 = 성과 배수, 구독자 밴드 티어링, raw 조회수 강등, 신뢰도 하한(최근 유형별 ≥10)·절대조회수 하한·극단배수(>25x) 플래그.
10. **레이트리밋** — 정식 API는 IP 차단 없이 쿼터/레이트로 실패(403 지수 백오프). 운영자의 과거 스크래핑 차단은 API 채택으로 해소. 유일 예외 = `/shorts` 프로브(post-MVP).

### 9.2 Cost

- 임베딩 월 운영비는 신규 영상만 과금(영상당 1회)이라 **월 $1 미만**(대개 수십 센트) 수준이다. 최초 백필(자사 500 + 경쟁 과거분 ~1.5만) ≈ $0.3~0.5 1회성.
- 진짜 월 고정비는 API가 아니라 상시 실행 서버 호스팅(소형 VPS 월 $5~10)이다. 임베딩 결제·지출 상한을 연결한다.

### 9.3 Data

- 스냅샷 보존 = 최근 90일 일단위, 이후 주단위 롤업 후 원본 삭제 + 주기적 VACUUM. 용량이 아니라 핫셋을 작게 유지하기 위함이다.
- 자사 회원 전용 영상 데이터는 수집·표시 대상이되 조회수는 nil로 취급한다.

## 10. Integration & Dependencies

- **YouTube Data API v3** (필수) — 조회수·메타·구독자. 무료(쿼터 내). 본개발 초기에 실제 응답으로 배치 크기(playlistItems/videos.list 50)·필드 존재(likeCount/commentCount 누락)를 재확인해야 한다.
- **gemini-embedding-001** (필수, 유료) — 유사영상·주제 묶기. YouTube와 같은 Google 계정, 다른 키. 무료 티어 의존 금지. 대안 = Voyage(200M 토큰 무료 한도), BGE-M3 로컬(외부 의존 제거 원할 때).
- **Ruby on Rails 8 / SQLite / Tailwind CSS** — 확정 스택. 운영자가 직접 코드 수정을 전제로 선택. 파이썬 아님.
- **Solid Queue** — 반복 작업 스케줄러, SQLite 저장, Redis 불필요.

## 11. Information Architecture

목업(`Planning/목업 샘플.png`)이 확정 IA다. 좌측 내비 + 상단 헤더 + 본문 위젯 그리드.

- **좌측 내비** — 대시보드 / 인기 콘텐츠 / 경쟁 채널 / 콘텐츠 갭 / 저장한 영상 / 설정. 하단에 데이터 범위(YouTube 전체: 한국어 + 일본어 시장) 안내.
- **상단 헤더** — 제목 "YouTube 콘텐츠 리서치" + 부제 "다음 주 제작할 주제를 10분 안에 결정하세요" + 검색바 + "오늘 업데이트" + 사용자 아바타 2인.
- **필터 바** — 기간 탭(최근 1주 / 1개월 / 3개월 / 에버그린) + 카테고리·유형 드롭다운(한국어 교육 / 영어 교육 / 일반 영상 + Shorts).
- **본문** — ①이번 주 추천 콘텐츠 3개(카드) ②급상승 영상(테이블) ③경쟁 채널 동향 ④콘텐츠 기회(도넛) ⑤에버그린 콘텐츠.
- **라벨 정합(강제)** — 목업의 "구독자 대비 조회수 N배"는 "성과 배수(채널 평소 대비) N배"로 전면 교체한다. 시각 레이아웃은 유지하고 문구만 방법론에 맞춘다.
